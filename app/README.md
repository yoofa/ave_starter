# Audio Latency Measurement System

这是一个用于测量音频回声延迟的系统，通过播放测试信号并录制环境声音来检测延迟。

## 系统架构

系统包含以下主要组件：

1. **LatencyMeasure**: 核心延迟测量算法，使用带通滤波器和波峰检测
2. **SimpleAudioAsyncPlayer**: 异步音频播放器，循环播放5秒测试信号
3. **SimpleAudioAsyncRecorder**: 异步音频录制器，持续录制环境声音
4. **Measurer**: 协调播放和录制的管理器

## 测试信号

- 测试信号频率: 4000 Hz (默认)
- 信号持续时间: 30ms (默认)
- 总缓冲区长度: 5秒
- 信号位置: 从1秒开始播放

## 编译

```bash
# 生成构建文件
gn gen out/Default

# 编译
ninja -C out/Default app
```

## 运行

```bash
# 运行延迟测量系统
./out/Default/latency_measure_main
```

## 使用方法

1. 运行程序后，系统会自动初始化音频设备
2. 开始播放测试信号（5秒循环）
3. 同时开始录制环境声音
4. 系统会持续分析录制的音频数据，检测回声延迟
5. 当检测到延迟时，会在控制台输出结果
6. 按 Ctrl+C 停止程序

## 配置参数

可以通过修改 `measurer.h` 中的常量来调整系统参数：

- `kDefaultCoreSignalFreqHz`: 测试信号频率 (默认: 4000 Hz)
- `kDefaultCoreSignalDurationMs`: 信号持续时间 (默认: 30ms)
- `kDefaultPeakThreshold`: 波峰检测阈值 (默认: 0.05)
- `kRecordPlaybackSampleRate`: 采样率 (默认: 48000 Hz)
- `kRecordPlaybackChannelCount`: 通道数 (默认: 2)

## 音频设备要求

系统需要支持以下音频配置：
- 采样率: 48000 Hz
- 格式: PCM 16-bit
- 通道: 立体声 (2通道)

## 注意事项

1. 确保系统有可用的音频输入和输出设备
2. 测试环境需要有一定的回声（如房间、会议室等）
3. 避免在完全消声的环境中测试
4. 系统会自动循环播放测试信号，无需手动干预

## 故障排除

如果遇到音频设备问题：
1. 检查音频设备是否被其他程序占用
2. 确认系统音频权限设置
3. 检查音频设备驱动是否正常
4. 在Linux系统上，确保ALSA或PulseAudio正常工作

## 系统分析与修复

在对代码进行审查后，发现系统的整体架构设计是合理的，但存在一些关键的实现错误，这些错误已得到修复。

### 问题1：`Measurer` 初始化逻辑错误

- **问题描述**: `Measurer` 类在其构造函数和 `Init` 公共方法中都对内部模块（特别是 `AsyncLatencyMeasure`）进行了初始化。这导致在 `main.cc` 中通过构造函数传递的配置参数被随后调用的 `Init()` 方法的默认参数覆盖，使得系统始终使用默认值运行。
- **修复方案**: 将所有初始化逻辑统一到 `Measurer` 的构造函数中，并移除了 `Init` 方法。为了确保所有音视频模块在正确的任务线程上被安全地初始化，构造函数内部使用了 `PostTaskAndWait` 来同步等待初始化完成。这样既简化了接口，也保证了对象在创建后立即可用。

### 问题2：录音循环延迟不正确

- **问题描述**: 在 `Measurer::ReadDataAndMeasure` 方法中，系统每次读取10毫秒的音频数据，但下一次读取的延迟被错误地设置为5000毫秒。这会导致音频设备的录音缓冲区在两次读取之间严重溢出，造成大量的音频数据丢失，从而无法进行有效的延迟测量。
- **修复方案**: 将 `PostDelayedTask` 的延迟从硬编码的 `5000` 毫秒修正为 `kReadChunkMs`（即10毫秒），确保录音数据的读取速度与产生速度相匹配，避免数据丢失。

### 问题3：播放器循环可能导致CPU占用过高

- **问题描述**: `SimpleAudioAsyncPlayer::Play` 方法在完成一次数据写入后，使用 `PostTask` 立即调度下一次播放，中间没有任何延迟。如果音频设备驱动的 `Write` 调用是非阻塞的，这将形成一个“忙等待”循环，可能导致单个CPU核心的占用率达到100%。
- **修复方案**: 将 `PostTask` 修改为 `PostDelayedTask`，并增加了 `kWriteChunkSizeMs`（10毫秒）的延迟。这可以避免CPU的空转，并使播放器的行为与录音器保持一致，形成一个稳定、高效的播放循环。

通过以上修复，系统的稳定性、正确性和性能都得到了显著提升，现在能够可靠地执行其预定的音频延迟测量功能。
